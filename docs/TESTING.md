# Retail testing — Xbox Store / Game Pass 1.5.6

This is a **retail prerelease**, not a stable release. Installable packages are generated by GitHub Actions from versioned repository source and published through GitHub Releases.

## Known bad candidate

**Do not use `v0.1.0-rc.1`.** Retail testing proved that it disabled both Escape and Xbox Start pause because it emitted wrong-case `consoleCmd="1"` and had no vanilla fallback.

The next candidate is `v0.1.0-rc.2`.

## 1. Install rc2

Download the ZIP asset from the `v0.1.0-rc.2` GitHub prerelease and extract `clean_pause` to:

```text
%USERPROFILE%\Documents\kingdomcome_mods\
```

Expected structure:

```text
Documents\kingdomcome_mods\clean_pause\
  mod.manifest
  Data\clean_pause.pak
```

Close KCD2 before replacing rc1. Remove/replace the old `clean_pause` directory rather than layering files over it.

For this test, disable any other mod that replaces `Libs/Config/defaultProfile.xml`.

## 2. Front-end/controller safety

Before testing the pause feature:

1. launch KCD2 with the Xbox controller connected;
2. verify normal navigation in the title/front-end menu;
3. load a save;
4. verify movement, camera, A/B/X/Y, triggers, shoulders, sticks, D-pad and View work normally.

If unrelated controller input is broken, stop and remove the mod.

## 3. First check: Escape and Xbox Start must never be dead

Test both controls separately in normal exploration.

### Successful Clean Pause route

Press Escape or Xbox Start.

Expected immediately on **press**:

- world/game progression freezes;
- current frame stays visible;
- no vanilla pause overlay appears;
- the button's subsequent release does not open the vanilla menu.

Expected log source names:

```text
[Clean Pause] official runtime loaded; routed actions=clean_pause_enter_gameplay,clean_pause_enter_pause_context
[Clean Pause] entered clean pause from clean_pause_enter_gameplay
```

In dialogue/cutscene the entry source should instead be:

```text
clean_pause_enter_pause_context
```

### Fail-safe result

If the custom command still cannot execute, **Escape/Start must at least open the normal vanilla pause menu when the button is released.**

This is an intentional safety fallback. Report this result as:

```text
vanilla fallback works; Clean Pause entry failed
```

### Invalid result

If Escape/Start again does absolutely nothing on both press and release, stop testing. That means the fail-safe invariant itself failed.

## 4. Clean Pause input isolation

Once Clean Pause is active, try:

- A/X/Y;
- D-pad;
- shoulders/triggers;
- both sticks;
- View/Back.

Expected: no gameplay/dialogue/cutscene action and no camera movement.

This validates `priority="overlays" exclusivity="1"` on the target build.

## 5. B resume

While clean-paused, press and release B once.

Expected:

```text
[Clean Pause] resumed
```

Gameplay resumes normally.

In dialogue/cutscene B must **not** skip/cancel anything. B press is a sink; resume is deliberately on B release.

## 6. Second Escape/Start -> vanilla pause menu

Enter Clean Pause again, then press Escape or Xbox Start.

Expected:

- real vanilla KCD2 pause menu opens;
- there is no intermediate gameplay unpause;
- log contains:

```text
[Clean Pause] handed pause ownership to vanilla menu
```

Close the vanilla menu normally with B. The game must return to ordinary running gameplay and Clean Pause must not reactivate automatically.

If second Start/Escape does nothing, look for:

```text
MenuEvents.DisplayIngameMenu(true) unavailable
```

or another `MenuEvents` error in `kcd.log`.

## 7. Subtitle acceptance

1. Start a dialogue with subtitles visible.
2. Wait for a clearly readable subtitle line.
3. Press Start.
4. Leave Clean Pause active longer than the line would normally remain.
5. Confirm the **same subtitle remains visible**.
6. Confirm speech/progression has stopped.
7. Press/release B.
8. Confirm dialogue resumes from the same point without skip, duplicate line or desync.

Repeat in at least one in-engine cutscene.

## 8. Scenario matrix

| Scenario | Clean Pause enters | zero overlay | frame fixed | subtitle retained | B safe resume | second Start vanilla menu |
| --- | --- | --- | --- | --- | --- | --- |
| Exploration | required | required | required | n/a | required | required |
| Combat | required | required | required | if present | required | required |
| Dialogue | required | required | required | **required** | **required** | required |
| In-engine cutscene | required | required | required | **required** | **required** | required |
| Mounted gameplay | required | required | required | if present | required | required |

Prerendered video is a separate capability test and may be engine-limited.

## 9. Robustness

After the core matrix passes, check:

- repeated pause/resume cycles;
- pause near subtitle/cutscene transitions;
- Clean Pause -> vanilla menu;
- loading a save from that menu;
- death/game-over;
- controller reconnect;
- Alt-Tab;
- return to main menu.

No case may leave the game unexpectedly paused or leave `clean_pause_controls` active after Clean Pause relinquishes ownership.

## Why rc2 is safer than rc1

The patched input cycle is now:

```text
press   -> custom consoleCMD entry
release -> original vanilla open_menu/open_pause_menu fallback
```

On successful custom entry, `clean_pause_controls` is enabled before release and its explicit Start/Escape release sink consumes that release.

If custom entry fails, the controls map never becomes active, so release reaches the original KCD2 pause action. CI verifies both paths are present in the actual release PAK.

## Uninstall

Close the game and delete:

```text
%USERPROFILE%\Documents\kingdomcome_mods\clean_pause
```

No controller/profile repair should be necessary.

## Stable-release gate

Do not publish stable `v0.1.0` until all are true:

- title/front-end controller behaviour is unchanged;
- Escape and Xbox Start cannot become dead controls;
- Clean Pause works in gameplay/dialogue/in-engine cutscene;
- first pause shows zero vanilla-menu frame;
- subtitle remains visible while paused;
- audio/progression pauses coherently;
- unrelated input is isolated;
- B resumes without underlying context side effects;
- second Start opens the untouched vanilla pause menu;
- repeated transitions leave no stuck pause/input state.
